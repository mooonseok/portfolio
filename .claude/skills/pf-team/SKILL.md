# 포트폴리오 팀 진행표

메인 세션이 **리드**입니다. 리드는 설계·분배·합치기·커밋만 하고, 구현과 검증은
서브에이전트에게 맡깁니다.

## 역할

| 담당            | 고치는 곳                                         | 하는 일                       |
| --------------- | ------------------------------------------------- | ----------------------------- |
| 리드(메인)      | 작업 지시서, 계약 파일, 합치기                    | 분배, 충돌 해결, 커밋, 보고   |
| data-builder    | dto, constants, content, lib(화면 외), api, tests | 타입·순수 함수·서버 데이터    |
| ui-builder      | components, sections, styles, app 페이지          | 스펙대로 뷰·스타일            |
| scene-builder   | lib/orbit·opener·diorama, 관련 hooks              | three.js 장면, GSAP 타임라인  |
| qa-runner       | 없음(읽기 전용)                                   | §5 검사, 4개 폭 캡처, G2 측정 |
| design-reviewer | 없음(읽기 전용)                                   | G3 미감·접근성 점수           |
| perf-auditor    | 없음(읽기 전용)                                   | 예산·Lighthouse·3D 성능       |
| copy-editor     | 없음(읽기 전용)                                   | 문구·커밋 제목                |
| docs-keeper     | README, HANDOFF, DESIGN.md                        | 실제 diff 기준 문서 갱신      |

## 단계

1. **작업 지시서(리드, 5분 이내).** 목표, 통과 기준(어느 경로·폭에서 무엇이
   0이어야 하는지), 담당별 소유 파일 목록, 담당 사이의 계약(공유 타입·토큰
   이름)을 대화에 씁니다. 같은 파일을 두 담당에게 주지 않습니다.
2. **계약 고정(직렬).** 여러 담당이 함께 쓰는 dto·constants·토큰은 리드나
   data-builder 한 명이 먼저 만들고 커밋합니다. 이후 담당은 계약을 바꾸지 않고,
   바꿔야 하면 보고합니다.
3. **병렬 구현.** 구현 담당을 한 메시지에서 동시에 띄웁니다. 각자
   `isolation: worktree`로 따로 작업하고, 지시서·소유 목록·계약·검사 명령만
   받습니다. 빌드와 서버 실행은 하지 않습니다.
4. **합치기(리드).** 담당별 브랜치를 작업 브랜치에 합치고 `pnpm typecheck`,
   `pnpm check:boundaries`로 이음매를 확인합니다.
5. **병렬 검증.** qa-runner(§5·캡처·G2), design-reviewer(G3), 필요하면
   perf-auditor·copy-editor를 한 메시지에서 동시에 띄웁니다. 3100번 서버는
   qa-runner만 띄우고, 다른 검토 담당은 qa-runner가 띄운 동안 같은 주소를 보거나
   캡처 폴더를 읽습니다.
6. **수정 라운드(최대 2회).** 지적마다 그 파일의 소유 담당에게만 돌려보냅니다.
   2회 뒤에도 남으면 남은 지적과 함께 사용자에게 넘깁니다.
7. **문서와 커밋.** docs-keeper가 문서를 맞추고, 리드가 `pf-commit`으로 목적별
   커밋합니다. push·PR은 사용자가 요청할 때만 합니다.

## 속도 규칙

- 이미 확정된 방향(테마·토큰·타임시트)을 옮기는 일은 시안·Artifact를 다시 만들지
  않고 바로 3단계로 갑니다. 새 방향을 정할 때만 `pf-design`의 G1을 거칩니다.
- 지시서에는 결론과 경로만 씁니다. 담당에게 대화 전체를 넘기지 않습니다.
- 검증은 담당별로 반복하지 않고 합친 뒤 한 번에 합니다. 담당은 정적 검사만
  돌립니다.
- 서로 의존하는 일(계약 → 구현)은 직렬, 독립적인 일은 항상 병렬로 띄웁니다.
