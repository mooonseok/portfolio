# 포트폴리오 디자인 진행표

화면 하나를 한 단위로 진행합니다. 먼저 `PRODUCT.md`, `DESIGN.md`, HANDOFF.md
§4~6을 읽습니다. 시안과 프로토타입은 Artifact로 보여 주고 레포에 파일을 만들지
않습니다.

## 단계

1. **요구 카드.** `frontend-design` 스킬로 주제, 보는 사람(채용 면접관·팀 리드),
   이 화면이 할 한 가지 일, 사용자가 이미 정한 금지 사항(예: 첫 화면 제목·소개
   문구 없음)을 대화에 적습니다.
2. **레퍼런스 분해.** 사용자가 준 레퍼런스와 `design-taste-frontend`,
   `awesome-design-md`에서 고른 것을 구성·움직임·재질로 나눠 쓸 것과 버릴 것을
   정합니다.
3. **부품 시안 → G1 · 사용자 선택.** 장면 전체보다 먼저 핵심 부품(행성·위성,
   테마)을 실제 화면 크기(데스크톱과 22px 안팎의 휴대폰 크기)로 2~4개 그려
   비교합니다. 사용자가 고르기 전에는 장면을 만들지 않습니다.
4. **스펙과 타임시트.** 상태(기본·선택·호버·움직임 줄이기·3D 불가)별 모양과,
   비트별 시간·이징 표를 정합니다. `pf-motion` 진행표를 따릅니다.
5. **프로토타입.** 고른 안만 단일 HTML로 만듭니다. 검증용으로 장면을 직접 그리는
   훅(`__settle`, `__seek`, `__phase`, `__hover`)과 측정 함수를 함께 둡니다.
6. **G2 · 기능 관문.** 1440×900, 1280×800, 1024×768, 834×1112, 744×1024,
   430×932, 390×844, 375×667, 360×740, 320×568, 844×390에서 회전 32~64단계마다
   이름표 겹침, 메뉴·패널과의 겹침, 화면 밖 넘침, 행성이 패널 밑으로 들어가는
   경우를 셉니다. 모두 0이어야 다음 단계로 갑니다.
7. **G3 · 미감 관문.** `design-reviewer` 서브에이전트에 화면 주소, 원본 경로,
   검증 훅, 확인할 폭만 넘깁니다. 고유성·위계·디테일·움직임이 각 7점 이상이면
   통과입니다. 고친 뒤 다시 보는 것은 최대 2회이고, 그래도 남으면 사용자에게
   남은 지적과 함께 넘깁니다.
8. **G4 · 사용자 확인.** 게시한 시안을 사용자가 확정하면 토큰(`impeccable`),
   문구(`copywriting` → `humanize-korean` → `design:ux-copy`), `pf-build` 순서로
   레포에 옮깁니다. 문구는 `src/content`에만 둡니다.

## 지킬 것

- 상태를 색으로만 구분하지 않습니다(기호 + 글자). 프로젝트 구별은 색이 아니라
  무늬와 실루엣으로 합니다.
- 중요한 내용을 호버에만 두지 않습니다. 터치에서는 첫 탭에 선택하고, 이동은
  패널의 링크로만 합니다.
- 겹침은 숨겨서 피하지 않고 빈자리로 옮겨서 피합니다.
- 강조색은 한 가지를 정해진 자리(선택 상태)에만 씁니다.
- 제목 줄에 한 단어만 남지 않게 합니다(`word-break: keep-all`).
- 확인되지 않은 수치, 임시 문구, 과장 표현을 넣지 않습니다. 비공개 레포는 링크를
  두지 않고, 모의 운용은 실거래로 쓰지 않습니다.
- 흔한 AI풍 구성(보라 그라데이션 히어로, 모든 요소 가운데 정렬, 모든 카드에 같은
  둥근 모서리와 그림자)을 피합니다.
