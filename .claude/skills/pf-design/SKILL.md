# 포트폴리오 디자인 진행표

화면 하나를 한 단위로 진행합니다. 먼저 `PRODUCT.md`, `DESIGN.md`, HANDOFF.md
§4~6을 읽습니다.

## 단계

1. **브리프.** `frontend-design` 스킬로 주제, 보는 사람(채용 면접관·팀 리드), 이
   화면이 할 한 가지 일을 정합니다. 브리프는 대화에 씁니다.
2. **방향 시안 2~3개.** `design-taste-frontend`로 방향을 잡고, 필요하면
   `awesome-design-md`에서 레퍼런스 토큰을 읽습니다. 시안에는 항상 **현재
   화이트보드 정체성 유지안**과 **새 방향안**을 함께 넣습니다. 비교 화면은
   Artifact로 보여 주고 레포에 파일을 만들지 않습니다.
3. **G1 · 사용자 선택.** 사용자가 고르기 전에는 코드를 쓰지 않습니다.
4. **토큰.** `impeccable`로 색, 글꼴 단계, 간격, 모서리, 모션 시간 토큰을 정하고
   `src/styles/tokens.css`, `DESIGN.md`, `.impeccable/design.json`을 함께
   갱신합니다.
5. **문구.** `copywriting`으로 초안 → `humanize-korean`으로 윤문 →
   `design:ux-copy`로 버튼·빈 상태·오류 문구를 다듬습니다. 문구는
   `src/content`에만 둡니다.
6. **구현.** `pf-motion`, `pf-build`로 넘깁니다.
7. **독립 리뷰.** `design-reviewer` 서브에이전트에 결과 화면 경로와 폭만
   넘깁니다. 지적을 고친 뒤 다시 보는 것은 최대 2회이고, 그래도 남으면
   사용자에게 넘깁니다.

## 지킬 것

- 상태를 색으로만 구분하지 않습니다(기호 + 글자). ● PRODUCT WORK / ◇ EXPERIMENT
  구분을 유지합니다.
- 중요한 내용을 호버에만 두지 않습니다. 호버로 커지는 카드도 터치에서는 첫 탭에
  펼치고 두 번째 탭에 이동합니다.
- 제목 줄에 한 단어만 남지 않게 합니다.
- 확인되지 않은 수치, 임시 문구, 과장 표현을 넣지 않습니다.
- 흔한 AI풍 구성(보라 그라데이션 히어로, 모든 요소 가운데 정렬, 모든 카드에 같은
  둥근 모서리와 그림자)을 피합니다.
