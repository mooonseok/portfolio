# 포트폴리오 모션 진행표

전역 `engineering-workflow`의 `references/design.md`를 읽고 아래 GSAP·three.js
기준을 적용합니다. 전역 스킬이 없는 환경에서는 AGENTS.md §7과 `pf-design`을
따릅니다. 기존 모션 기준은 HANDOFF.md §5에 있습니다.

입력은 승인된 모션 목적·타임시트와 상태별 대체 경로입니다. 새 움직임은 코드보다
시간표를 먼저 합의하고, 이미 승인된 시간표는 바로 구현합니다. 산출물은
장면·타임라인과 검증할 구간입니다. 기능 실패는 해당 모션 담당에게, 방향 변경은
디자인 선택 노드로 돌려보냅니다. QA의 서버 준비 후 프레임을 확인하고 영향을 받은
G2·G3로 연결합니다.

## 단계

1. **성격.** `motion-design` 스킬로 이 화면의 움직임이 줄 인상 한 가지를 정하고,
   이징과 속도 범위를 고릅니다.
2. **타임시트.** 비트별로 무엇이, 몇 ms 동안, 어떤 이징으로 움직이는지 표로 써서
   사용자에게 보여 줍니다. 합의 내용을 작업 상태에 기록하고 실제 구현이 끝나면
   HANDOFF.md §5 모션 표에 반영합니다.
3. **구현.**
   - DOM·SVG: `gsap-timeline`, `gsap-react`(`useGSAP`, 언마운트 정리), 글자
     분리와 선 그리기는 `gsap-plugins`.
   - 3D: `threejs-interaction`(레이캐스팅 호버·클릭), `threejs-animation`.
   - GSAP는 이미 승인된 의존성입니다. 현재 설치와 기존 구현을 재사용하고, 새
     애니메이션 의존성은 사용자에게 먼저 확인합니다.
4. **미세 조정.** `emil-design-eng`로 호버 확대(약 200ms), 누를 때 반응, 끝맺음
   이징을 다듬습니다.
5. **대체 경로.**
   - 움직임 줄이기 설정: `gsap.matchMedia()`로 짧은 페이드(약 0.3초)나 완성
     상태로 바꿉니다.
   - 3D를 쓸 수 없는 환경: 기존 3D 로딩 판단 함수(`src/lib/diorama-load.ts`)를
     재사용해 2D로 보냅니다.
   - 스플래시는 탭 세션당 1회, 클릭이나 키 입력으로 건너뛸 수 있어야 합니다.
6. **프레임 확인.** `agent-browser`로 구간별 화면을 캡처해 타임시트와 맞는지
   봅니다. 끊기면 `gsap-performance`, `threejs-performance`로 원인을 찾습니다.

## 지킬 것

- 스크롤 프레임마다 React 상태를 바꾸지 않습니다. 값은 CSS 변수나 data 속성으로
  씁니다.
- transform과 opacity만 애니메이션합니다. 레이아웃 속성은 움직이지 않습니다.
- 스플래시는 서버에서 그린 실제 내용 위에 덮는 방식으로 만들어 LCP 요소가 글자로
  남게 합니다.

- 승인된 궤도 회전과 오프닝은 프로젝트 모션 사양으로 평가합니다. Unslop의
  일반적인 반복 모션 금지보다 사용자 승인 사양을 먼저 적용하고, 대체 경로와 조작
  가능성을 검증합니다. 모션 수정도 같은 산출물의 수정 횟수에 포함합니다.
