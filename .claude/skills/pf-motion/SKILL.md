# 포트폴리오 모션 진행표

움직임은 코드보다 시간표를 먼저 합의합니다. 기존 모션 기준은 HANDOFF.md §5에
있습니다.

## 단계

1. **성격.** `motion-design` 스킬로 이 화면의 움직임이 줄 인상 한 가지를 정하고,
   이징과 속도 범위를 고릅니다.
2. **타임시트.** 비트별로 무엇이, 몇 ms 동안, 어떤 이징으로 움직이는지 표로 써서
   사용자에게 보여 줍니다. 합의한 표는 HANDOFF.md §5 모션 표에 행으로
   추가합니다.
3. **구현.**
   - DOM·SVG: `gsap-timeline`, `gsap-react`(`useGSAP`, 언마운트 정리), 글자
     분리와 선 그리기는 `gsap-plugins`.
   - 3D: `threejs-interaction`(레이캐스팅 호버·클릭), `threejs-animation`.
   - GSAP는 2026-10-29에 추가가 승인됐습니다. 첫 모션 구현 브랜치에서
     `pnpm add gsap`으로 넣고, 다른 애니메이션 라이브러리는 사용자 확인 없이
     추가하지 않습니다.
4. **미세 조정.** `emil-design-eng`로 호버 확대(약 200ms), 누를 때 반응, 끝맺음
   이징을 다듬습니다.
5. **대체 경로.**
   - 움직임 줄이기 설정: `gsap.matchMedia()`로 짧은 페이드(약 0.3초)나 완성
     상태로 바꿉니다.
   - 3D를 쓸 수 없는 환경: 기존 3D 로딩 판단 함수(`src/lib/diorama-load.ts`)를
     재사용해 2D로 보냅니다.
   - 스플래시는 탭 세션당 1회, 클릭이나 키 입력으로 건너뛸 수 있어야 합니다.
6. **프레임 확인.** `agent-browser`로 구간별 화면을 캡처해 타임시트와 맞는지
   봅니다. 끊기면 `gsap-performance`, `threejs-performance`로 원인을 찾습니다.

## 지킬 것

- 스크롤 프레임마다 React 상태를 바꾸지 않습니다. 값은 CSS 변수나 data 속성으로
  씁니다.
- transform과 opacity만 애니메이션합니다. 레이아웃 속성은 움직이지 않습니다.
- 스플래시는 서버에서 그린 실제 내용 위에 덮는 방식으로 만들어 LCP 요소가 글자로
  남게 합니다.
