# 포트폴리오 커밋 진행표

개편 후에는 커밋 제목이 홈 화면 작업 현황 카드에 그대로 보입니다. 제목은 이
레포를 모르는 사람이 읽어도 뜻이 통해야 합니다. 기본 규칙은 AGENTS.md §3입니다.

## 순서

1. `git status`, `git diff --staged`로 변경을 봅니다. 목적이 둘 이상이면 나눠서
   스테이징합니다.
2. `pf-verify`의 검증이 통과했는지 확인합니다. 통과 전에는 커밋하지 않습니다.
3. 제목과 본문을 씁니다.
4. `git commit`을 실행합니다. `.githooks/commit-msg`가
   `scripts/check-commit-message.mjs`로 메시지를 검사합니다. 실패하면 메시지를
   고쳐 다시 커밋합니다. `--no-verify`는 쓰지 않습니다.
5. push, PR 생성, merge는 사용자가 요청할 때만 합니다. PR 제목도 같은 제목
   규칙을 따릅니다.

## 제목

- "무엇을 + 어떻게 바꿨는지". 끝은 추가·보완·정리·연결·교체·제거 같은
  명사형입니다.
- 36자 이내. `feat:` 같은 영어 접두어, 마침표, "~했습니다" 같은 서술형을 쓰지
  않습니다.
- 내부 설정값, 환경 변수, 비밀값, 파일 이름 대신 사용자가 보는 변화로 씁니다.
- "대폭", "완벽" 같은 과장 표현을 쓰지 않습니다.

## 본문

- 제목 다음 빈 줄, 그 아래 `- `로 시작하는 항목 3~5개. 실제로 한 일만 씁니다.
- 공동 작성자 트레일러나 도구 서명을 넣지 않습니다.

```
마인드맵 노드 호버 확대 추가

- 노드와 정보 카드를 200ms 동안 확대
- 연결선 강조와 나머지 노드 흐리게 처리
- 터치에서는 첫 탭 펼침, 두 번째 탭 이동
- 움직임 줄이기 설정에서 확대 생략
```

이렇게 쓰지 않습니다: `feat: hover 구현 및 여러가지 수정사항 반영`,
`fix: production cookie SameSite=None`, `마인드맵 대폭 개선했습니다`.
