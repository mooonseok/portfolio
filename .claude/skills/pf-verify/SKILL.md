# 포트폴리오 검증 진행표

전역 `engineering-workflow`의 `references/development.md`와
`references/state.md`에 아래 프로젝트 검사를 연결합니다. 전역 스킬이 없는
환경에서는 AGENTS.md §5~7과 이 절차를 따릅니다. 실행 담당은 `qa-runner`입니다.

## 입력과 결과

- 입력은 검증 모드(`prototype` 또는 `project`), 작업 경로, 수용 조건, 화면·모션
  변경 여부, 산출물 버전, 독립 검토자 목록입니다. `prototype` 버전은 Artifact
  HTML과 의존 자원을 식별하며, `project` 버전에는 HEAD와 작업 중 변경분 식별
  정보를 함께 담습니다.
- 결과는 명령·종료 코드·근거 경로, 캡처의 폭·상태, 통과·실패·미검증 항목입니다.
  실패하면 실행 중인 검증 노드의 결과를 리드에게 반환합니다. 리드가 담당자
  수정이나 환경 복구로 연결하고, 수정 뒤 영향받은 검증 노드에서 재개합니다.
- 같은 입력의 유효한 결과는 재사용합니다. HTML·의존 자원·코드·설정·검사 입력이
  바뀌면 관련 결과를 무효화합니다. 프로젝트 변경의 최종 커밋 상태에서는
  AGENTS.md §5 전체의 유효한 통과 결과가 필요합니다.
- 검사 규칙과 예산은 수용 기준입니다. 검증을 통과시키려고 약화하거나 테스트를
  지우지 않습니다. 실행하지 못한 검사는 미검증으로 남깁니다.

## 프로토타입 검증 모드

레포 밖 시안의 G2·G3는 `prototype` 모드를 사용합니다. 프로젝트 소스가 바뀌지
않은 시안 검증에는 프로젝트 빌드를 요구하지 않습니다. 프로젝트 파일도 바뀌었다면
그 변경은 별도로 `project` 모드의 검사를 통과해야 합니다.

1. QA가 Artifact HTML 원본 경로와 버전, 이미지·글꼴·모듈 등 의존 자원의 위치를
   확인합니다. 실행에 필요한 자원이 누락되면 프로토타입 담당에게 반환합니다.
2. 브라우저에서 직접 열어 정상 동작하는 시안은 해당 파일을 엽니다. 모듈이나 자원
   로딩 때문에 HTTP가 필요하면 기존 가용 도구로 Artifact 디렉터리만 제공하는
   로컬 정적 서버를 127.0.0.1의 3100번에 띄웁니다. 포트 확인·소유·종료 규칙은
   프로젝트 서버와 같습니다. 실행 가능한 도구가 없으면 미검증 이유를 반환합니다.
3. QA가 실제 시안의 화면·자원 로딩을 확인한 뒤 모드, 원본 경로, 브라우저 주소,
   버전, 서버 PID(직접 파일을 연 경우 없음)를 포함한 준비 신호를 보냅니다.
4. QA는 `pf-design`의 G2 폭·상태·회전 측정을 수행합니다. 독립 G3 리뷰어는 같은
   준비 신호와 시안 버전을 받아 확인합니다. 수정 후에는 관련 G2·G3로
   재진입합니다.
5. 모든 검토자의 사용 완료 후 QA가 직접 연 브라우저와 정적 서버를 정리합니다.
   서버를 띄웠다면 `ps`와 `lsof`로 종료를 확인합니다. 실패·사용자 대기에도
   자원을 정리하고 현재 시안의 근거와 미검증 항목을 반환합니다.

## 프로젝트 검증 모드

프로젝트 구현 변경에는 `project` 모드로 AGENTS.md §5 전체를 실행합니다.

1. `pnpm format:check` → `pnpm lint` → `pnpm typecheck`
2. `pnpm test` → `pnpm check:boundaries`
3. QA가 `lsof -nP -iTCP:3100 -sTCP:LISTEN`으로 포트를 확인합니다. 직접 띄운 개발
   서버는 종료하고, 다른 프로세스가 쓰고 있으면 해당 자원의 충돌을 보고합니다.
   개발 서버 종료가 확인된 뒤 `pnpm build`를 실행합니다.
4. `pnpm check:anchors` → `pnpm check:metadata` → `pnpm check:perf`
5. 화면 변경 시 QA가 `pnpm start --port 3100`으로 서버를 띄우고, 실행 경로·코드
   버전·PID를 포함한 준비 신호를 보냅니다. `agent-browser`로 390 / 744 / 1024 /
   1440px와 관련 선택 상태, 키보드 이동, 움직임 줄이기 상태를 확인합니다.
   `pf-design` G2가 필요한 장면은 그 진행표의 추가 폭·회전 단계도 측정합니다.
6. 독립 검토자는 준비된 서버를 사용합니다. `perf-auditor`의 성능 측정은 다른
   브라우저 작업과 시간을 분리합니다. QA는 모든 검토자의 사용 완료를 모읍니다.
7. QA가 직접 띄운 서버·브라우저를 PID 기준으로 종료하고 `ps`와 `lsof`로 종료를
   확인합니다. 오류·중단·사용자 대기 시에도 같은 정리 절차를 실행합니다.

## JS 크기 예산

- `scripts/verification/perf-budget.json`의 경로별 첫 로딩 JS(gzip)와 가장 큰
  청크 예산을 적용합니다.
- 새 경로의 예산 추가와 예산 상향은 측정값을 제시하고 사용자에게 확인합니다.
- 초과하면 dynamic import, 중복 의존성 제거 등 원인을 담당자에게 반환합니다.
  승인된 예산 변경은 `baseline` 설명과 함께 반영한 뒤 재검증합니다.

## 보고와 종료

필수 검증이 통과하면 다음 노드로 이동할 수 있다는 결과를 리드에게 반환합니다.
실패는 재현 조건과 첫 오류 위치를, 미검증은 이유를 함께 반환합니다. 화면 확인은
실제 브라우저 근거를 붙입니다. 수정 횟수는 리드가 관리하는 작업 상태를 사용하며
검증 노드에 재진입해도 초기화하지 않습니다.
